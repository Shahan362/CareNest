2. Application structure

How the React code is organised. Pages show data; hooks load and save it through the Supabase client; the lib/ files hold the business rules (clash checks, billing maths, UK formatting).

Business rules shown as operations

Scheduling

  • Visit.conflictsWith(): a caregiver can't be booked for two overlapping visits (cancelled visits don't count). The app warns but allows "Save anyway".
  • Visit.isBillable(): only completed visits can go on an invoice.
  • Caregiver.assignedHours(week): compared with maxHoursPerWeek to show workload.

Billing

  • InvoiceLine.unitPrice copies the patient's hourly rate when invoiced, so later rate changes don't alter old invoices.
  • A visit can appear on at most one invoice line (visitId {unique}).
  • Invoice.displayStatus() works out Overdue and Part paid from the due date and payments.
  • Invoice.void() keeps the record and frees its visits to be billed again.

Accounts & security

  • Signing up as a caregiver or patient requires a valid Agency.code.
  • If the admin already created a record with the same email, the new login is linked to it (userId) instead of creating a duplicate.
  • The Profile.role decides which pages a user can open, and the database only returns rows from the user's own agency.
